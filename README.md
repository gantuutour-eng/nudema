# Nudema Mongolia

**Nudema**의 뷰티·의료용품·생활용품 등 여러 제품군을 위한 쇼핑몰 + 관리자 페이지.

[Claude Design](https://claude.ai/design)의 `.dc.html` 형식으로 작성되었으며,
모든 페이지가 `nudema-store.js`를 통해 같은 데이터를 사용합니다.
Cloudflare 배포에서는 Pages Functions + D1이 기기 간 공유 저장소이며,
`localStorage`는 빠른 로딩과 로컬 미리보기를 위한 캐시/폴백으로 사용됩니다.

## 페이지

| 파일 | 설명 |
|---|---|
| `index.html` | 정적 폴백·OAuth 설명 페이지. 운영 루트는 `functions/index.js`가 주소를 유지한 채 PC/모바일 홈을 내부 제공 |
| `menu.html` | 전체 페이지 목록 (개발·시연용) |
| `Nudema Mongolia.dc.html` | PC 홈 |
| `Nudema Mobile.dc.html` | 모바일 홈 (390px) |
| `Nudema Product.dc.html` | 상품 상세 (`?id=1`) |
| `Nudema Checkout.dc.html` | 결제 |
| `Nudema Admin.dc.html` | 관리자 (PC) |
| `Nudema Admin Mobile.dc.html` | 관리자 (모바일) |

운영 환경에서는 아래의 짧은 공개 URL을 사용합니다. 기존 `.dc` 및
`.dc.html` 주소는 호환성을 위해 대응하는 짧은 URL로 영구 이동합니다.

| 공개 URL | 페이지 |
|---|---|
| `/` | 기기에 맞는 쇼핑몰 홈 |
| `/admin` | 기기에 맞는 관리자 |
| `/login`, `/signup`, `/account` | 고객 인증·계정 |
| `/search`, `/product?id=1` | 검색·상품 상세 |
| `/cart`, `/checkout` | 장바구니·결제 |
| `/privacy`, `/terms` | 개인정보 처리방침·이용약관 |

`/`와 `/admin`은 서버에서 기기를 감지해 같은 URL을 유지한 채 PC 또는
모바일 화면을 제공합니다. 기존 긴 PC 주소로 직접 들어온 모바일 사용자는
`device-redirect.js`가 각각 `/?v=mobile` 또는 `/admin?v=mobile`로 정리합니다.
`?v=pc`를 붙이면 PC 화면을 강제로 확인할 수 있습니다.

## 관리자 기능

### 여러 제품군의 상품 등록

분류는 **대분류 → 카테고리 → 상품**의 2단계 카테고리 구조입니다.
기본 대분류는 `Гоо сайхан`(뷰티), `Эмнэлгийн хэрэгсэл`(의료용품),
`Гэр ахуй`(생활용품), `Бусад`(기타)이며 새로운 대분류를 추가할 수 있습니다.
기존 화장품 카테고리와 상품은 유지하고, 기존 카테고리에는 뷰티 대분류를 연결합니다.

1. **상품 → 카테고리/태그 관리**에서 대분류를 만들고 하위 카테고리를 등록합니다.
2. **새 상품**에서 이름, 대분류, 카테고리, 상품 유형, 가격·재고를 입력합니다.
3. SKU, 브랜드, 제조사, 원산지, 판매 단위, 유효기간을 필요에 따라 입력합니다.
4. **유형별 사양 양식**을 불러오거나 이름–값 형식으로 자유롭게 사양을 추가합니다.
   의료용품에는 등록번호·용도·멸균 여부·보관 조건·주의사항,
   생활용품에는 재질·크기·관리 방법 등을 입력할 수 있습니다.
5. 저장 후 고객용 홈의 대분류 메뉴와 검색 필터, 상품 상세 정보에 반영됩니다.

상품 유형과 카테고리는 별개입니다. 카테고리는 고객 탐색용이고 상품 유형은 입력 양식용입니다.
SKU를 입력하면 중복을 검사합니다. 현재 가격·재고는 음수가 아닌 정수 단위이며 가격은 0보다 커야 합니다.
카테고리명은 기존 데이터 호환을 위해 전체 대분류에서 유일해야 합니다.
분류 이름을 변경하면 연결된 상품도 갱신하며, 사용 중인 분류는 바로 삭제할 수 없습니다.

저장 구조는 기존 `app_state` JSON에 `taxonomy.departments`, `taxonomy.categoryDepartments`,
상품의 `productType`, `sku`, `brand`, `manufacturer`, `country`, `unit`, `expiryDate`,
`specifications: [{ name, value }]`를 추가하는 방식이라 별도 DB 마이그레이션이 필요 없습니다.
카테고리 이름 변경은 `/api/admin/catalog`에서 taxonomy와 products를 같은 D1 배치에 저장합니다.
등록번호 등의 필드는 제품 정보를 기록하는 기능이며 인허가 검증이나 처방 확인 기능은 포함하지 않습니다.

로컬 관리자에는 **Локал демо нээх**(로컬 데모 열기) 버튼이 표시됩니다.
이 모드는 `localhost:4321` 또는 `127.0.0.1:4321`에서만 동작하고 해당 브라우저에 저장합니다.
운영 서버 인증과 운영 데이터에는 연결되지 않습니다.

- **대시보드** — 매출·주문·회원·평균주문액, 최근 7일 차트, 인기상품 (모두 주문 데이터에서 계산)
- **주문** — 상태 필터, 검색, 상세 모달, 상태 변경
- **상품** — 등록·편집·삭제, 이미지 갤러리(최대 8), 상세 블록 에디터(텍스트/구분선/이미지/영상/조합형)
- **회원** — 주문에서 집계, 지출 기준 등급
- **사용자 계정** — D1 회원가입·로그인, PBKDF2 비밀번호 해시, HttpOnly 세션, 내 주문·포인트 조회
- **리뷰** — 숨김·답변·삭제, 필터
- **콘텐츠** — 상단 마퀴, 히어로 슬라이드(추가/삭제/이미지 업로드), 브랜드 영상
- **통계** — 월별 매출, 카테고리 비중
- **설정** — 상점 정보, 무통장입금 계좌, 카테고리/태그, 관리자 계정

### 모바일 관리자 (`Nudema Admin Mobile.dc.html`)

하단 탭 5개(대시보드 · 주문 · 상품 · 콘텐츠 · 설정)로 구성된 앱 형태이며,
PC 관리자와 같은 `nudema-store.js` · `/api/admin-auth` · D1을 그대로 씁니다.
앱바의 `‹` 버튼이 화면·상세 시트 이동 기록을 되돌립니다.

PC 전용 화면은 아직 옮기지 않았습니다 — **회원, 리뷰, 통계**, 그리고
멤버십 배너 편집은 PC 관리자에서만 가능합니다.

## 로컬 실행

고객 화면은 [UI Bowl의 퀸잇 레퍼런스](https://uibowl.io/name/%ED%80%B8%EC%9E%87)의 메뉴·메인·상품 상세 구성을 참고합니다.
홈은 검은 선택 탭, 둥근 배너, 두 줄 이미지 바로가기와 상품 사진 중심 목록으로 구성합니다.
`/search#departmentFilter`는 왼쪽 대분류·오른쪽 이미지 목록인 전용 메뉴 화면이며,
일반 `/search`는 기존 검색·필터 화면입니다. 두 화면은 같은 상품과 관리자 분류를 읽습니다.
상품 상세는 사진·브랜드·실제 할인 가격·배송/옵션·구매 순서로 표시하고,
모바일에서는 공통 하단 메뉴 대신 장바구니·구매 버튼을 고정합니다.
몽골어 문구와 공식 로고, 기존 검색·장바구니·로그인·결제 연결을 사용합니다.
상단 검색창은 홈에서만 표시하며 모바일 홈에서는 검색 아이콘으로 접근합니다.
모바일 검색의 대분류·카테고리 선택란은 한 줄로 배치합니다.
`storefront-ui.js`는 공통 고객용 컴포넌트입니다. 기존 `storefront.css` 및
`storefront-addwel.css` 다음에 `storefront-queenit.css`를 로드해 색상·서체·간격·카드와
입력 폼을 조정합니다. 이 테마는 `nd-storefront`에만 적용하며 관리자 화면에는 적용하지 않습니다.
홈은 첫 화면의 색상 깜박임을 줄이도록 head와 디자인 런타임 helmet에 같은 순서의 스타일 참조를 둡니다.
배너는 PC/모바일 모두 한 프레임씩 이동하며 슬라이드 폭과 이동 계산을 100%로 맞춥니다.
이전 `storefront-musinsa.css`는 캐시된 구버전 문서 호환을 위해 남겨 두며 새 페이지는 로드하지 않습니다.
관리자는 `admin-theme.css`의 청록색·밝은 배경·파스텔 카드 스타일을 사용합니다.
사진이 없는 상품에만 `assets/storefront/*.svg` 기본 일러스트를 표시하며,
관리자가 등록한 실제 상품 이미지를 우선 사용합니다.
첨부된 공식 로고는 `assets/brand/nudema-logo.svg`이며 고객 헤더·푸터와 PC/모바일 관리자에 공통 적용합니다.
상단 안내 문구와 고객센터·푸터 정보는 관리자 저장 시 열린 화면에도 반영됩니다.

결제 페이지는 도시/아이막 → 구/솜 → 동/박을 선택하고 상세 배송주소를 직접 입력합니다.
지역 목록은 `mn-regions.js`를 사용합니다. 지도·주소 검색 위젯과 Leaflet은 주문서에서 로드하지 않으며,
선택한 지역과 상세주소를 합쳐 주문에 저장합니다. 배송비와 기존 필수 입력 검증은 유지합니다.
기존 주문의 좌표 데이터 및 기존 클라이언트용 `/api/geocode` API는 그대로 유지합니다.

```bash
node serve.js
# http://localhost:4321/
# Windows의 회사 인증서를 사용하는 환경: node --use-system-ca serve.js
```

로컬 서버도 운영 환경과 같은 `/`, `/admin`, `/product` 등의 페이지 주소를 제공합니다.
PC·모바일 홈은 `/?v=pc`, `/?v=mobile`로 각각 확인할 수 있습니다.
관리자 로그인과 서버 인증 기능은 Cloudflare 배포 환경이 필요합니다.

`.dc.html`은 `support.js`(DC 런타임)가 있어야 렌더링됩니다.
React와 ReactDOM은 `assets/vendor`의 로컬 파일을 사용합니다. 외부 폰트·외부 이미지에는 인터넷 연결이 필요합니다.

Cloudflare Pages + D1 배포 방법은 [`CLOUDFLARE.md`](./CLOUDFLARE.md)를 참고하세요.

## 모바일 설치와 로딩

고객 화면 상단의 몽골어 설치 배너와 푸터의 `Nudema апп суулгах` 버튼은
브라우저가 `beforeinstallprompt`를 제공했을 때만 표시합니다. 사용자가 버튼을
누르면 설명 팝업 없이 브라우저의 네이티브 설치 창을 바로 엽니다.
설치 요청을 한 번 사용하면 버튼을 숨기고 새 요청 이벤트가 올 때만 다시 표시합니다.
배너를 닫거나 설치를 거절하면 상단 배너는 7일 동안 숨깁니다.
iPhone/iPad와 일부 내장 브라우저는 설치 요청 API가 없어 버튼을 표시하지 않습니다.
iOS에서는 브라우저 공유 메뉴의 `Add to Home Screen`으로 설치할 수 있습니다.
이미 설치된 앱의 독립 실행 화면에서도 설치 버튼을 숨깁니다.

`manifest.webmanifest`와 PNG 앱 아이콘, `sw.js`를 사용합니다. 서비스 워커는
오프라인 안내만 저장하고 상품 가격·계정·주문 API는 캐시하지 않습니다.
상품 사진 업로드는 계속 WebP를 사용하며, 운영 상품에서도 WebP MIME과 RIFF 시그니처를 확인했습니다.

모바일 오류는 캐시된 구버전 `nudema-store.js`와 새 화면의 API 불일치로 재현됐습니다.
공통 스크립트의 버전을 통일하고 스토어를 렌더링 전에 한 번만 초기화합니다.
Cloudflare Browser Cache TTL은 `Respect Existing Headers`로 설정합니다.
공통 메뉴·푸터는 React가 관리하는 DOM을 교체하지 않고 별도 노드에서 렌더링합니다.
상세 이미지는 지연 로드·비동기 디코딩하며 상세 블록은 3개씩 더 볼 수 있습니다.
공개 상품 이미지는 변경되지 않는 키를 기준으로 Cloudflare 엣지 캐시를 재사용합니다.

| 상품명·가격 변경 | 저장 직후 열려 있던 홈·검색·상품 상세에 반영. 테스트 후 원복 |
| 카테고리 추가·삭제 | 홈 필터·검색 선택지에 즉시 반영. 임시 분류 삭제 완료 |
| 메인 배너·배송비 변경 | 열린 고객 화면에 즉시 반영. 테스트 후 원복 |
| 상단 안내·푸터 | 기존 표시 연결 누락을 수정. 공통 헤더·푸터가 저장 이벤트를 구독 |
| 마이페이지 | 로컬 인증 API 404를 오류 문구만으로 처리하던 문제 수정. 로그인 화면과 로컬 서버 안내 표시 |
| 배송 위치 | 실제 몽골 주소 검색·지도 타일·장소 선택 확인. 좌표가 주문에 저장되는 API 검증 통과 |
| 다른 기기 반영 | 운영 코드는 15초 주기 조회. 로컬 저장은 같은 브라우저·같은 origin에 한정 |

현재 동작 점검 현황(PR #9 반영분 포함):

1. **재고 차감 (r3 수정)**: 새 주문 성공 시 재고와 주문을 한 배치로 저장합니다. 취소는 한 번 복원하고, 취소 재활성화는 재고를 다시 확보합니다. 과거 주문은 소급하지 않습니다. 설명/카테고리 저장은 판매된 수량을 되돌리지 않으며, 충돌한 명시적 재고 변경은 새로고침을 요청합니다.
2. **주문 연결·새 주문 보존 (r3 수정)**: 상태 변경은 단일 주문 PATCH를 사용합니다. 회원 연결·생성 시각과 다른 주문을 보존하고, 예전 전체 저장 경로는 409로 차단합니다. 과거에 손실된 연결을 복구한 것은 아닙니다.
3. **취소·매출·포인트 기준**: 11/17 회원 API와 화면에서 `cancel`·`cancelled`를 같은 취소로 읽도록 수정했습니다. 관리자 매출의 결제 확정 기준과, 회원 포인트가 미결제 주문을 포함한 합계의 2%인 점은 운영 정책을 정해 통일해야 합니다.
4. **기능과 다른 기본 안내 (r3 정정)**: 15% 할인·생일 쿠폰·24시간 자동 취소 약속을 현재 기능에 맞게 정정하고, 작동하지 않는 이메일 알림 스위치를 제거했습니다. 해당 기능을 새로 구현하거나 사용자 지정 문구를 일괄 변경하지 않았습니다.
5. **리뷰 집계**: 상품의 리뷰 수·평점은 별도 상품 필드이며 실제 리뷰 목록은 상품명 단어로 연결합니다. 상품 ID 기반 연결과 실제 집계가 필요합니다.
6. **서버 저장 완료 표시 (11/17 보완)**: 카테고리·태그·상위 분류는 서버 응답 후 반영합니다. 다른 저장의 기존 낙관적 편집 방식은 유지하되, 관리자 공통 표시가 전송·실패·서버 완료를 구분합니다. 같은 탭의 쓰기는 FIFO로 전송하며 실패 스냅샷 재저장을 지원합니다. 자세한 계약과 기기 간 동시 편집의 한계는 상태 머신 감사 문서를 참고하세요.
7. **로컬 인증**: `node serve.js`는 고객/관리자 인증·D1 API를 실행하지 않습니다. 실제 회원가입·로그인·기기 간 공유는 Cloudflare Functions/D1 환경에서 별도 확인해야 합니다.

## ⚠️ 알아두실 점

- 운영 관리자 API는 서버 세션으로 인증합니다. 로컬 데모 진입은 운영 인증을 대체하지 않습니다.
- 일반 정적 서버(`node serve.js`)에서는 데이터가 `localStorage`에만 저장됩니다. Cloudflare 운영 배포에는 `DB` 이름의 D1 바인딩과 migrations 적용이 필요합니다.
- 주문·회원·리뷰의 시드 데이터는 **데모용 가상 데이터**입니다.
- `support.js`, `image-slot.js`는 Claude Design이 생성한 런타임 파일입니다 (직접 수정하지 마세요).
